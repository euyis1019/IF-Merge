# Flan-T5

Eight GLUE tasks (CoLA, MNLI, MRPC, QNLI, QQP, RTE, SST-2, STS-B) as text-to-text problems, with the
FusionBench prompts, experts and evaluation protocol, on Flan-T5-base and Flan-T5-large.

## Environment

```bash
pip install -e ".[t5,data]"
```

The scores are those of generated answers, so they depend on the generation code. Every Flan-T5 number in
the paper was measured with **Transformers 4.51.3, Tokenizers 0.21.4 and Hugging Face Hub 0.36.2**; the `t5`
extra pins the first two. Inputs are padded to 512 tokens, and Transformers 4.51 masks that padding during
generation while later major versions do not unless told to. This code passes the mask explicitly, which
removes the one difference we know of, but we have compared numbers only under the pinned versions: with
another version a warning is printed, and every `result.json` records the versions it was produced with.

## Data

```bash
if-merge prepare-t5 --size base          # about 9 GB
if-merge prepare-t5 --size large         # about 30 GB
```

| What | Source | Stored as |
| :-- | :-- | :-- |
| Pretrained model and tokenizer | `google/flan-t5-<size>` | `t5/models/<size>/pretrained/` |
| Base experts (fully fine-tuned) | `tanganke/flan-t5-base_glue-<task>` | `t5/models/base/<task>/` |
| Large experts (LoRA, rank 16) | `tanganke/flan-t5-large_glue-<task>_lora-16` | `t5/models/large/adapters/<task>/`, merged into full weights in `t5/models/large/<task>/` |
| GLUE | `nyu-mll/glue` | `t5/glue/<task>/<split>-*.parquet` |

The large experts are LoRA adapters on the query and value projections. `prepare-t5` adds each low-rank
update to the pretrained weights once, so that merging treats both sizes alike.

| Split | Content | Used for |
| :-- | :-- | :-- |
| validation | the GLUE validation split (`validation_matched` for MNLI) | every reported number |
| calibration draw `K` | the first 512 training examples of `torch.randperm` with seed `K`, prompts only | IF-Merge: the first 256 prompts are $C_t$ (statistics), the next 256 are $H_t$ (step selection). Calibration data of the other methods |
| selection draw `K` | 256 labeled training examples: from position 1024 of the same permutation on, skipping everything reserved for calibration under any seed | selecting the hyperparameters of baselines |

Tokenized splits and draws are cached in `t5/cache/<size>/` on first use.

## IF-Merge

```bash
if-merge t5 --size base --init wa                 # from Weight Averaging
if-merge t5 --size base --init ta --seed 1        # from Task Arithmetic, calibration draw 1
if-merge t5 --size base --init runs/t5/base/baselines/tsv_m/seed0/merged.safetensors
if-merge t5 --size base --init wa --set g.estimator=identity --freeze-head
```

`--init` takes `wa`, `ta`, `iso_c`, `iso_cts` (built at the scale listed in
[`configs/baselines/t5_selected.yaml`](../configs/baselines/t5_selected.yaml)) or any `merged.safetensors`.
The recipe is [`configs/if_merge/t5.yaml`](../configs/if_merge/t5.yaml); `--set section.field=value` changes
one field. A run writes `runs/t5/<size>/if_merge/<init>-seed<K>/`:

- `merged.safetensors`: the merged model with the lowest holdout KL;
- `result.json`: the holdout KL and step size of every round, the selected round, validation scores of the
  initialization and of the merged model, time, peak GPU and host memory, the recipe and the overrides.

What is specific to Flan-T5 (App. "Adapting IF-Merge to CLIP and T5"):

- The expert answers each unlabeled prompt by greedy decoding; its answer is the decoder input of both the
  expert and the merged model. Positions up to and including the end-of-sequence token are the valid
  prediction positions.
- The feedback loss is the teacher-student KL of each valid prediction position divided by that position's
  chi-square scale. Statistics are accumulated over non-padding encoder positions and valid decoder
  positions; the key and value projections of cross-attention read encoder positions.
- One step size is selected for the full model. The token embedding, layer norms and position biases keep
  the values of the initialization. The vocabulary head is fitted with $G = I$, or kept with `--freeze-head`.
- Supported `g.estimator` values: `normalized_kl`, `kl`, `mc_fisher`, `identity`.

## Baselines

```bash
if-merge t5-baseline --size base --method tsv_m               # select the hyperparameter, then evaluate
if-merge t5-baseline --size base --method ta --value 0.3      # fixed hyperparameter, no labeled data
if-merge t5-baseline --size base --method regmean --seed 1 --value 0.9
```

Methods: `wa`, `ta`, `ties`, `tsv_m`, `wudi`, `iso_c`, `iso_cts`, `fisher`, `regmean`, `regmeanpp`, `mats`,
`adamerging`, `featcal`. Settings and grids are in [`configs/baselines/t5.yaml`](../configs/baselines/t5.yaml).
A hyperparameter with a grid is selected by the average score on selection draw `--seed`; a scale whose best
value is the last grid point keeps stepping until three values in a row fail to improve. The validation
split is evaluated once, for the selected value. `--seed` also picks the calibration draw of the
data-dependent methods. Results go to `runs/t5/<size>/baselines/<method>/`.

The main-text table lists Task Arithmetic and Iso-C at fixed scales (0.3 and 1.3) and the other baselines
with selected hyperparameters. IF-Merge (TA) on base starts from the selected scale 0.25, on large from 0.3.
Target-feature interpolation (the last appendix table) is an extension that is not part of this code.

How closely a rerun matches: the data pipeline, the evaluation and the weight-space baselines are
deterministic and reproduce the reference weights and scores exactly. IF-Merge from Weight Averaging on
Flan-T5-base (seed 0) reproduces the holdout KL of every round and all eight task scores of
`results/t5.json` to the last digit on the hardware and library versions above. On other hardware or
versions expect small differences: every conjugate-gradient solve stops after 100 iterations, and a few
weight matrices are fitted from inputs of very low rank (the first decoder self-attention sees little more
than the start token), where the truncated solve amplifies floating-point rounding; a change in the last
digits of a weight can move the per-round holdout KL by about 1e-3 relative and the average score by a few
hundredths of a point.

## Memory and time

Measured on one 48 GB GPU.

| Run | Time | Peak GPU | Peak host RAM |
| :-- | --: | --: | --: |
| IF-Merge, base (4 rounds, without evaluation) | 8 min | 10.5 GiB | 32 GiB |
| IF-Merge, large (4 rounds, without evaluation) | 20 min | 31-41 GiB | 132-231 GiB |
| Baselines with a selection sweep, base (with evaluation) | 15-20 min | 2.4 GiB | 17-52 GiB |
| GLUE validation, base / large | 6 / 18 min | 2.4 / 6.7 GiB | 7 GiB |

Host memory is dominated by the statistics: one $A_t$ and one $G_t$ per weight matrix and task, kept on the
CPU while the layers are solved on the GPU. For Flan-T5-large this is about 57 GiB per round (16 GiB for
base), next to the experts' weights and predictions. Our Flan-T5-large runs peaked between 132 and 231 GiB
of host memory, the higher figure when the statistics of the first round were kept as well; plan for a
machine with 256 GiB of RAM. AdaMerging on large holds the task vectors of all experts on the
GPU (41 GiB).

## Evaluation

`if-merge t5-evaluate --size base --checkpoint <merged.safetensors | pretrained | experts>`

Each prompt is padded to 512 tokens and answered by greedy decoding of at most ten decoder positions. A
prediction counts as correct when the generated text equals the reference answer exactly; STS-B reports
100 x the Spearman correlation between generated and reference scores, with unparsable answers counted as 0.
The average weights the eight tasks equally.
